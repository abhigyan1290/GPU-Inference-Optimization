# Phase 1 methodology

The measured operation is a batch of greedy causal-LM generation with KV caching, eager attention, and a fixed number of new tokens. No compilation or runtime optimization is enabled. A fixed English sentence is tokenized without added special tokens, then repeated/truncated to the exact prompt length. Rows are identical and unpadded. This simplifies controlled experiments but is not representative of all production traffic.

The default seed is zero. Evaluation and inference modes disable dropout and autograd. Seeds do not guarantee bitwise reproducibility across GPUs or library versions. Record model and tokenizer revision, software lock, seed, prompt digest, dtype, batch size, input/output lengths, attention implementation, and device information. The tokenizer and model use the same resolved revision; remote Python code is disabled and only safetensors weights are loaded.

Load model and prepare inputs before timing. Run warm-up generations with the same workload. Before each generation, synchronize CUDA and reset peak memory counters. Start perf_counter, call generate, synchronize again, and stop the timer. CUDA kernels execute asynchronously: an unsynchronized host timer can measure enqueue time rather than completion. This measurement includes host orchestration, scheduling gaps, and device work. It excludes tokenization, loading, transfer of prepared inputs, and text decoding. CUDA event timings or profiler kernels would answer different questions.

For each measured run, store elapsed seconds and actual generated token count from tensor dimensions. Disable EOS stopping and require the exact requested length. Validate the prompt prefix and output dimensions. Throughput = sum of generated tokens over all measured runs / sum of measured generation seconds. Prompt tokens are excluded from its numerator but prefill is included in time. Median is the conventional sample median; p95 is the sorted sample at ceil(0.95*n)-1 (nearest rank). Do not call total latency divided by output length TPOT: it includes prefill and first-token cost. TTFT and TPOT are null, not estimated.

Record peak allocated and peak reserved bytes for each run. Counters include resident model, inputs, and generation allocations after resetting the peak to current usage; they do not measure model-loading peaks. Reserved memory can retain the warm-up allocator pool. These counters are not whole-device VRAM use: driver/context and other applications consume memory too. Output tensors are released between runs. Do not empty the cache between iterations, since that changes steady-state behavior.

Ten repeats are a starting point; p95 from three smoke repetitions is effectively the maximum and is not a stable tail estimate. Warm-up may need to be longer for other workloads. Keep the laptop plugged in, power settings consistent, and other GPU applications quiet. Record temperature, power, competing workloads, and variance before interpreting results. Compilation, autotuning, caching, thermal throttling, or changing CPU/GPU clocks can contaminate comparisons. Future compile experiments must separately document compilation and steady-state costs.

Compare equal model revisions, prompt tokens, output tokens, batch sizes, and generation semantics. Change one independent variable at a time, documenting exceptions. Raw JSON is local and ignored by Git; intentionally archive selected results with matching code and environment when making a claim. A smoke run verifies the harness only; no speedup or bottleneck attribution follows from it.
